01 / AGENT BENCH

Bring the receipts.

Compare measured runs. Different kinds of test stay separate.

No numbers invented here. Load the measured sample or import a local run.
Run your own benchmark
npm run bench
TYPESAFE_API_KEY=… npm run bench -- --live

The first is a keyword baseline. The second sends task text to TypeSafe. Use an environment file instead of pasting your key into a command history. These measure action selection, not a complete browser session. Use REPETITIONS=3 for repeated runs. Never compare API token costs with a subscription as though they were the same thing.

02 / BROWSER OBSTACLE COURSE

A button is rarely
just a button.

Twenty local tasks. No real account changes, purchases or messages. The timer begins when you start.

Ready when you are.

Delayed controls. Similar labels. A page that tells you to do the wrong thing. The usual.

What this measures

Your browser run records task completion, incorrect attempts and elapsed time, including pauses. The exported method is “Browser run · unlabelled operator”. It does not automatically know whether you or an agent clicked. Restarting a task records a failed attempt before trying again. Tasks 1–12 are development cases, 13–20 are a held-out split. Once you have tuned against them, create a new holdout.

03 / SKILL LAB

More instructions.
Better results?

Compare two instruction variants on the same labelled decisions. No text gets sent from this page.

Run the comparison locally
npm run skills -- skill-config.json

Set TYPESAFE_API_KEY in your environment first. Maximum ten cases, two variants, twenty calls. Import reports/skills.json in Bench. This evaluates Jev instructions, not a full coding skill. A longer skill is not automatically a better one.

04 / RELEASE CHECK

It deployed.
Open it anyway.

Check the live URLs, then exercise the flows that HTTP cannot see.

Automated smoke checks cover status, HTML, expected page markers and viewport metadata. They do not prove layout or interactions work.

Run after a deployment
npm run release

Reads six fixed public project URLs. It never submits forms. Failing checks exit with a non-zero code. Import reports/release.json in Bench and use the checklist for manual or supported browser-tool QA.

05 / CLAIM CHECK

Cool claim.
Where’s the source?

Check the evidence before it becomes a post. An exact quote is only the first step.

Optional model-assisted review
npm run claims -- claim.json

This local command sends the supplied claim and source to TypeSafe. Use public material or data you are authorized to share. Keep private messages and credentials out. Import reports/claim.json in Bench. A model verdict still needs a source check before publication.
